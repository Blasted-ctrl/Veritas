# Veritas

## 1. DESIGN PHILOSOPHY

Keep the media visible and the assessment readable. Use cool green paper, deep green ink, Hanken Grotesk, and a flat inspection panel. The original brief is an Operate surface: choosing and inspecting a file outranks visual spectacle.

## 2. CRAFT RULES

Use the semantic tokens in design-model.yaml. Keep source and assessment adjacent on desktop, stacked on mobile. Give type a clear hierarchy and use one green accent. Panels use 16px corners, controls 8px. No decorative shadows. Tabler outline icons use 1.5px strokes. All scores are predictions, and illustrative examples are labeled.

## 3. ANTI-PATTERNS

Avoid gradient headlines, ornamental grids, invented accuracy claims, glowing panels, and dashboard statistics unrelated to the selected media. Never add an eyebrow above a heading. Monospace is for code and hashes; percentages retain the body font. Never ship an em dash in visible copy.

## 4. WORKFLOW

Read the model, tokens, and component references. Match existing product behavior before extending the system. Render light and dark themes at desktop and mobile widths. Check contrast, keyboard access, cancellation, error recovery, long filenames, expanded details, and real inference before shipping. Keep DESIGN.md synchronized with accepted system changes.
